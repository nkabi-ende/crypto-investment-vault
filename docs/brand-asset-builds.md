# Brand assets across deployment paths

The Open Graph image and invitation image are generated by `scripts/generate_brand_assets.py` from the checked-in CIV mark and seven-asset SVG artwork. Keep the resulting production PNGs checked in as well as the generator. The GitHub production workflow regenerates these images, while a direct Cloudflare Workers build can deploy the repository assets without that Python generation step. Both paths must have the same current image URLs available.

A live smoke check caught `/og-invitation-v3.png` returning 404 after a direct build replaced a workflow deployment: that new image was generated in CI but absent from the repository. The current raster assets now ship in the repository, including the v3 invitation image. The public-asset test checks the PNG signatures and 1200×630 dimensions of the sharing images referenced by the frontend before CI's generation step runs.

When changing the brand image or its URL, regenerate with the pinned Pillow/CairoSVG versions from the deployment workflow, review the result, commit the changed raster assets, and run both the repository checks and live social-preview smoke check. Re-running a deployment without fixing the missing artifact is not a durable fix.
