# CIV application security review — 17 November 2026

Scope: Cloudflare Worker and static routing, authentication, session/cookie handling, private account/KYC/payment APIs, reviewer resources, frontend rendering/storage, dependencies, deployment checks and tracked Git history. Tests use isolated synthetic accounts and documents. Live checks are limited to public headers and unauthenticated/rejected requests; no customer documents or funds are accessed.

## Changes

| Boundary | Enforced behavior |
| --- | --- |
| Static and dynamic responses | Every request passes through the security boundary. HTML has a fresh script nonce, strict CSP, frame protection, HTTPS/HSTS, referrer protection and restricted browser capabilities. The existing TradingView frame and fonts remain explicitly allowed. Inline styles remain allowed because the current design uses them; arbitrary inline scripts and event-handler attributes are blocked. |
| Browser/CDN caches | HTML, APIs, reviewer resources, errors and redirects explicitly prohibit storage in browser, shared CDN and Cloudflare CDN caches. Private responses vary on cookie/origin. Public JS/CSS/images contain no customer data and can retain normal asset caching. |
| Session cookies | Host-bound Secure/HttpOnly/SameSite=Strict cookies, random 256-bit tokens with only their SHA-256 digests stored, rotation on authentication, server revocation on logout, duplicate-cookie rejection and a five-session cap. The old cookie is not accepted. |
| Session lifetime | Members: seven-day absolute maximum and 24-hour request inactivity limit. Assigned reviewers: eight-hour absolute maximum and 15-minute request inactivity limit. Server-side time checks apply to each authenticated request; these are request inactivity limits, not a promise of human-activity detection. |
| Password storage | New hashes use standard PBKDF2-HMAC-SHA256 with 600,000 iterations and per-user random salts. Both prior hash formats remain verifiable and upgrade atomically after a valid login. Passwords/hashes never appear in account APIs or browser assets. |
| Forged requests | Mutating APIs require the exact origin and an accepted content type; cross-site/same-site fetch metadata is rejected. CORS does not grant other sites credentialed access. Unsupported API methods fail closed. |
| Abuse | Platform rate limit before API database access, existing pre-hash authentication throttling, durable per-account failed-login lockouts, document quotas/size checks and payment/review-specific limits. Platform limits are per Cloudflare location and do not replace edge DDoS/WAF controls. |
| Authorization | Private route families require a server session. Account ownership comes from that session, never a supplied ID/slug/role header. Reviewer HTML, extensionless aliases, scripts, APIs and evidence downloads all require an enabled reviewer role. KYC decisions still require evidence checks and prohibit self-approval. |
| Browser session cleanup | Logout clears personal dashboard text/inputs, closes identity dialogs, removes pending-quote browser metadata, aborts stale private requests and notifies other open tabs. Cached-page restoration reloads through server authentication. Session-expired private requests leave the account view. |
| Source/dependency exposure | Sensitive artifact paths/source maps are refused. Pattern checks of public files run in tests; the reviewed tracked history had no matches for the checked provider credential/private-key patterns. npm audit reported zero known advisories at review time. CI and production deployment now reject high/critical dependency advisories. |

Migration 0017 adds versioned session timestamps. Existing sessions intentionally stop authenticating and users sign in again. Account records, funds, referral history and identity documents are preserved. No treasury signer or payout execution is enabled.

## Validation and operational limits

Automated tests cover two-account isolation, guessed/private routes, forged privilege headers, reviewer resources, nonce/markup consistency, early error headers, missing/cross-origin writes, content-type confusion, idle/absolute expiry, legacy-cookie refusal, session rotation/revocation/caps, hash upgrades, rate limiting and blocked artifact paths. Browser checks exercise the actual CSP policy with normal signup/dashboard scripts and cross-tab logout. Production smoke checks verify the deployed security headers and denied anonymous access.

Public page source, JavaScript, asset names and API URLs remain inspectable. They are not credentials. Access is enforced on the server even when a caller knows a URL or modifies the frontend. This review is a code hardening pass, not an independent penetration-test certification.

Account-side work remains outside this repository's verified scope: confirm phishing-resistant MFA on GitHub/Cloudflare, production branch/environment approvals, minimum-scope deployment tokens, WAF/bot/cache rules, audit-log alerting, backup/restore policy and operator access. Application reviewer MFA has not been implemented or enrolled; the reviewer gate currently requires password authentication, a fresh bounded session and the explicit reviewer role. KYC originals are signature/size checked and downloaded as sandboxed attachments; there is no external malware-scanning or identity-authenticity service. Document retention/deletion remains an operational responsibility. Registration still reveals whether an email can be registered through its result; suppressing that signal requires a verified-email onboarding flow, which is not configured.
